# RudStock API

Общие правила:
- деньги везде в копейках, `int64` (149.99 ₽ → `14999`)
- id карточки: UUID строкой; id категории: целое число
- ошибка всегда в формате `{"slug": "category-not-found", "msg": "Category not found"}`; `slug` стабильный машинный код, `msg` текст для пользователя
- доступ:
  - `public` без авторизации
  - `customer` любой вошедший пользователь (ручки `/me/*`); покупатель, но и сотрудник тоже может
  - `staff` сотрудник с ролью `manager`, `storekeeper` или `admin` (все ручки `/admin/*`); у ручки может быть указана конкретная роль
- пользователи в одной таблице с полем `role`: `customer` (покупатель, регистрируется сам) или роль сотрудника (создаёт только админ). Роль никогда не берётся из запроса на регистрацию
- токен передаётся в заголовке `Authorization: Bearer <access>`
- стиль REST: путь называет ресурс во множественном числе, действие задаёт HTTP-метод

## Админка

### POST /admin/cards

Создание карточки товара.

Доступ: `admin`

Запрос:
```json
{
  "category_id": 1,
  "title": "Michelin Primacy 4 205/55 R16",
  "description": "Шина летняя 205/55 R16",
  "price": 14999,
  "photo_url": "s3://photos/photo_1.jpg"
}
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| category_id | int64 | да | категория должна существовать |
| title | string | да | не пустое, пробелы по краям обрезаются |
| description | string | нет | |
| price | int64 | да | > 0, копейки |
| photo_url | string | нет | ссылка на объект в minio |

Ответ `201`:
```json
{ "card_id": "3f2b8c1e-6a1d-4c2e-9b7a-2d5f0e8a1c44" }
```

Ошибки:
| Код | Когда |
|---|---|
| 400 | невалидный JSON, category_id не передан (<= 0), пустой title (`invalid-title`), price <= 0 |
| 404 | категория не найдена |
| 500 | всё остальное |

---

### PATCH /admin/cards/{id}

Частичное обновление карточки: меняются только переданные поля.

Доступ: `admin`

Запрос (любое подмножество полей, хотя бы одно):
```json
{ "price": 12999, "description": "Шина летняя 205/55 R16, распродажа" }
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| category_id | int64 | нет | > 0, категория должна существовать |
| title | string | нет | не пустое, пробелы по краям обрезаются |
| description | string | нет | можно `""`, чтобы очистить |
| price | int64 | нет | > 0, копейки |
| photo_url | string | нет | можно `""`, чтобы очистить |

Поле отсутствует или `null` → не меняется. Неизвестное поле → 400.

Ответ `200`: карточка целиком после изменения, формат как у `GET /cards/{id}`.

Ошибки:
| Код | Когда |
|---|---|
| 400 | `id` не UUID, невалидный JSON, ни одного поля (`empty-patch`), category_id <= 0, пустой title, price <= 0 |
| 404 | карточки нет (`card-not-found`), новой категории нет (`category-not-found`) |
| 500 | всё остальное |

---

### DELETE /admin/cards/{id}

Удаление карточки. Пока физическое: заказов ещё нет. Когда появятся, станет архивированием (`status`), а для карточки в заказах вернёт 409.

Доступ: `admin`

Ответ `204` без тела.

Ошибки:
| Код | Когда |
|---|---|
| 400 | `id` не UUID (`invalid-path-param`) |
| 404 | карточки нет (`card-not-found`) |
| 500 | всё остальное |

---

### POST /admin/categories

Создание категории.

Доступ: `admin`

Запрос:
```json
{ "name": "Шины" }
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| name | string | да | не пустое, уникальное |

Ответ `201`:
```json
{ "category_id": 1 }
```

Ошибки:
| Код | Когда |
|---|---|
| 400 | невалидный JSON, пустое имя |
| 409 | категория с таким именем уже есть |
| 500 | всё остальное |

---

### PATCH /admin/categories/{id}

Переименование категории: меняются только переданные поля.

Доступ: `admin`

Запрос:
```json
{ "name": "Летние шины" }
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| name | string | нет | не пустое, уникальное, пробелы по краям обрезаются |

Поле отсутствует или `null` → не меняется. Пустой объект `{}` → 400. Неизвестное поле → 400.

Ответ `200`:
```json
{ "id": 1, "name": "Летние шины" }
```

Ошибки:
| Код | Когда |
|---|---|
| 400 | `id` не целое число, невалидный JSON, ни одного поля (`empty-patch`), пустое имя |
| 404 | категории нет (`category-not-found`) |
| 409 | имя занято другой категорией (`category-exists`) |
| 500 | всё остальное |

---

### DELETE /admin/categories/{id}

Удаление пустой категории. Если в ней есть карточки, сначала их нужно перенести (`PATCH /admin/cards/{id}` с новым `category_id`) или удалить.

Доступ: `admin`

Ответ `204` без тела.

Ошибки:
| Код | Когда |
|---|---|
| 400 | `id` не целое число (`invalid-path-param`) |
| 404 | категории нет (`category-not-found`) |
| 409 | в категории есть карточки (`category-has-cards`) |
| 500 | всё остальное |

### GET /cards

Список карточек, новые первыми, с пагинацией.

Доступ: `public`

Query-параметры:
| Параметр | Тип | Обязательно | Правила |
|---|---|---|---|
| category_id | int64 | нет | >= 0; нет или `0` → все категории; несуществующая → пустой список |
| page | int | нет | >= 0, с 1; нет или `0` → `1` |
| limit | int | нет | >= 0; нет или `0` → `20`; больше `100` → `100` |

Пример: `GET /cards?category_id=2&page=1&limit=20`

Ответ `200`:
```json
{
  "items": [
    {
      "id": "3f2b8c1e-6a1d-4c2e-9b7a-2d5f0e8a1c44",
      "category_id": 2,
      "title": "Michelin Primacy 4 205/55 R16",
      "description": "Шина летняя 205/55 R16",
      "price": 14999,
      "photo_url": "s3://photos/photo_1.jpg",
      "created_at": "2026-09-30T12:00:00Z"
    }
  ],
  "total": 1
}
```

`total` это число карточек под фильтром без учёта пагинации. Страница за концом списка → `items: []`, `total` прежний.

Ошибки:
| Код | Когда |
|---|---|
| 400 | параметр не целое число, отрицательный `category_id`, `page` или `limit` |
| 500 | всё остальное |

### Аутентификация (покупатели и сотрудники)

Вход по email и паролю, общий для всех ролей. Куда пускать дальше, решает роль.

| Ручка | Принимает | Возвращает | Ошибки | Описание |
|---|---|---|---|---|
| `POST /auth/register` | `email, password, name, phone?` | `201` access + refresh, `{user: {id, email, name, role}}` | 400 email / слабый пароль, 409 email занят, 429 | регистрация покупателя, роль всегда `customer`; сразу вход |
| `POST /auth/login` | `email, password` | access + refresh, `{user: {id, email, name, role}}` | 401, 403 заблокирован, 429 | вход. На неверный email и неверный пароль один и тот же 401, чтобы нельзя было перебором узнать, какие email есть |
| `POST /auth/refresh` | refresh | новая пара токенов | 401 | продление сессии, старый refresh перестаёт работать |
| `POST /auth/logout` | refresh | `204` | — | выход, refresh отзывается |
| `POST /auth/email/verify` | `token` из письма | `204` | 400 токен неверный / истёк | подтверждение email |
| `POST /auth/password/forgot` | `email` | `204` всегда | 429 | письмо со ссылкой сброса. `204` даже для несуществующего email, по той же причине, что и 401 у login |
| `POST /auth/password/reset` | `token, password` | `204` | 400 токен неверный / истёк, слабый пароль | новый пароль по ссылке из письма, все сессии пользователя отзываются |

Первый админ создаётся вне API (команда CLI или сид), дальше сотрудников заводит он через `/admin/users`.

Минимум для запуска (MVP): каталог, заказ (в том числе гостевой), регистрация/вход, `GET /me` и `GET /me/orders`, CRUD карточек/категорий, заказы в админке, приход/остатки — около 35.

## Отложено

- вход по SMS-коду как второй фактор (2FA): обязательный для сотрудников, по желанию для покупателей (`POST /me/2fa` включить/выключить, `POST /auth/2fa/verify` после login). Номер для этого уже есть в профиле (`phone`)
